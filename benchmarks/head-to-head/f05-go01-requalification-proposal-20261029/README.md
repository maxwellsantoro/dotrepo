## Bounded download-only preparation proposal

If separately authorized, one new preparation attempt would use the exact source/image and stop at 900 seconds, 1 GiB expanded exported-cache bytes or 512 MiB plain-tar transport bytes. It would run only the prior trusted package-manager sequence: root `npm ci --ignore-scripts`, then `go mod download` in each of `tsc/` and `tools/`. Common npm11.19.1 needs no alternate npm installation. The tools module pins gotestsum1.13.0; Herebyfile lines 1208–1218 builds it with `go install` during later offline wrapper setup. Building it online or exporting a task-specific binary is outside download-only preparation.

Only regular files from `npm-cache/_cacache` and `go/pkg/mod` would enter the cache archive. Checkout source, generated Git metadata, checkout node_modules/workspace links, build/test caches, tools/gotestsum, credentials and evaluation artifacts stay excluded. The lock has 249 package entries, three internal workspace links and registry-only external resolutions, each with integrity. No links are projected into a regular-file cache. Prior interface receive counters near 171 MB suggest acquisition may fit, but do not prove expanded/archive size or offline completeness. Hitting a cap must retain an incomplete receipt; no automatic pruning, narrower dependency set, larger quota or retry is proposed.

Normal contributor setup is `npm ci`, while old online preparation used `--ignore-scripts`. The lock marks install scripts for vsce-sign, dprint and esbuild; the inspected root and three workspace manifests have no install/prepare lifecycle scripts. Hook equivalence is still unresolved. A future epoch should freeze offline normal `npm ci` behavior from audited cache, or explicitly adjudicate the ignored hooks before treating the old variant as equivalent. Package scripts may fail offline or need system dependencies; that is an observable setup limitation, not a reason to declare them irrelevant. All proposal audit/admission flags remain false.

## Collection and oracle prerequisites

The exact intended native set has not been successfully collected. `static-test-inventory.json` is a lexical diagnostic only: 4,608 candidate `_test.go` files outside Go-ignored data/directories, 6,028 lexical top-level test/example/fuzz identifiers and 469 lexical skip sites. These counts include build/platform variants and benchmark/helper contexts; they are not expected executed-test counts. Successful native collection must bind actual platform/tags, the complete package set including zero-test packages, and applicable top-level identities before scoring execution.

A new task-specific oracle must be frozen before any run. It must read raw JSON events because the wrapper hides the skipped summary, check run and pass/fail terminal evidence for every active intended top-level identity and package, and examine skip events at every nesting depth. Wrong scope, collection/tool/build failures, missing or truncated events, resource/deadline failure, unexpected skips and changed tracked bytes remain noncompletion/unresolved. Complete assertion failures can be observed default-command outcomes with `testsPassed=false`; they must not be conflated with setup failure or incomplete coverage.

The old all-skips-reject oracle is preserved. It cannot be silently reused as a promise of successful qualification: source includes explicit disabled tests. `known-disabled-candidates.json` binds 377 exact fourslash identities, source hashes and locations with the literal reason `Known failing fourslash test`; e.g. `tsc/internal/fourslash/tests/aliasMergingWithNamespace_test.go:10–12` skips before its body. This is a candidate list, not an approved exclusion policy. Default `TestReplay` skips without a replay flag (`replay_test.go:42–49`); fuzz-seed predicates and platform/capability skips also need separate source-based decisions. The three bare lexical `t.Skip()` sites are not equivalent: one is a disabled fourslash test and two occur inside fuzz predicates. The inventory preserves that uncertainty.

Before any native attempt, the coordinator must freeze exact allowed identities, conditions and reasons; unexpected skips at any depth still prevent completion. Source-defined exclusions may support a declared default-suite outcome only under that explicit policy and never prove the excluded behavior ran. No global accept-skips rule, new test filter or capability/permission expansion is proposed. The existing 1,200-second collection-plus-test cap also needs an explicit next-epoch decision; this proposal does not enlarge it.
