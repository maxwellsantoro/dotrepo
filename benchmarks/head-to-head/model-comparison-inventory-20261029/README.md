Privacy and eligibility need explicit route-specific treatment. [Meta Contributor terms](https://dev.meta.ai/docs/pricing-rate-limits) permit training on submitted context and responses in exchange for the lower rate; Standard has different terms. Existing account rejection must be preserved, not bypassed. [OpenAI API data controls](https://developers.openai.com/api/docs/guides/your-data) exclude training by default unless opted in, with abuse-monitoring and endpoint storage exceptions. [Alibaba direct API policy](https://www.alibabacloud.com/help/en/model-studio/data-retention-policy) distinguishes normal retention from conditional enterprise ZDR and separate training consent. [Z.AI's API DPA](https://docs.z.ai/legal-agreement/privacy-policy) differs from its consumer policy and says supplied/generated API content is not stored. None of those direct-provider conditions automatically describes an arbitrary OpenRouter backend. [OpenRouter routing controls](https://openrouter.ai/docs/guides/routing/provider-selection) separately filter data collection and ZDR; this policy sets neither field, while account restrictions can still apply. Account/provider eligibility was not inspected.
