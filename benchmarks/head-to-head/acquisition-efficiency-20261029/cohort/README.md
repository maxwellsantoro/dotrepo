# Acquisition100 cohort selection, declared before comparison

Scope: freeze100 indexed GitHub repository identities and their existing recorded upstream revisions for a baseline/revised acquisition experiment. This is separate from F-05 preparation, field-quality acceptance, execution qualification and consumer-benefit evidence. No source acquisition, provider/native call or implementation comparison is performed here.

The declared seed is `dotrepo-acquisition100-20261029-v1`. Input is every regular `index/repos/github.com/<owner>/<repo>/record.toml` in the shared checkout at declared base `9fe76b4d` (full observed input hashes will be bound). Canonical identity is lowercase `github.com/<owner>/<repo>` from its index path. Eligible records must parse as TOML, have an exact lowercase40hex `x.github.head_sha`, have a matching GitHub `record.source` identity, and have an explicit first entry in `repo.languages`. That first entry is treated only as the **recorded primary language**: Rust→Rust, Python→Python, JavaScript or TypeScript→JS-TS, Go→Go. No inferred ecosystem, command, evidence confidence, acceptance, file count, source availability, stars or later acquisition result affects membership/rank. Other first languages remain outside this four-ecosystem sample, with no manual reclassification. Forks and archived records are not removed merely for those statuses.

Exclude canonical identities enrolled in the frozen E1 qualification cohort and F-05 task roster, plus exposed development identities `github.com/docker/compose`, `github.com/keras-team/keras`, and `github.com/zellij-org/zellij`. Bind the exact exclusion-roster files and complete union. Ambiguous duplicate canonical index identities, missing/malformed revisions or source/language eligibility facts are excluded explicitly, never repaired by a live lookup.

Within each of the four groups, rank ascending by lowercase hex SHA256 of UTF-8 `seed + NUL + group + NUL + canonicalIdentity`, then canonical identity as tie-break. Take the first25 per group, without inspecting upstream sources or evaluated field dispositions. Emit the final cohort ordered by groups Rust, Python, JS-TS, Go and within group rank. Stop rather than inventing categories if any eligible pool has fewer than25. All eligibility/rank input fields and record hashes, pool counts and exclusions are retained for reproducibility. Exactly one opportunity per selected identity/revision; selected failures/missing sources in the eventual experiment remain assigned, with no replacement.

`head_sha` is the index's recorded provenance selection. It is not freshly resolved HEAD, recent upstream inspection, proof the commit remains available, or a field-quality assessment. Later acquisition must target the exact selected revision and retain inability/partial disposition. No stale identity/revision may be silently replaced.

The future baseline/revised comparison must use these same opportunities, requests and disposition semantics, and freeze implementation/limits/cache conditions before running. Cold and warm conditions need distinct declared cache state and order; report all assigned outcomes, requests and transferred bytes, wall/CPU/RSS and planning/selection/verification/fallback/maintenance effort. Caches, failed attempts and missing measurement values cannot be hidden or converted to zero. This paragraph defines measurement intent, not a current frozen run protocol or results. Root/measurement owners define the bounded comparison; this cohort packet creates no new executor or run authorization.

This selection rule is source-independent with respect to the compared acquisition implementations and upstream success/dispositions. It uses an already-indexed, ecosystem-stratified population and known exclusion history, so it is not a fresh independent holdout or a representative sample of all GitHub repositories. No target source trees were copied and no repository input was edited.
