# E1: source-grounded instruction establishment

Use the [shared boundaries and freeze rules](README.md). This packet evaluates
whether sources establish a task-applicable instruction, independently of whether
an agent benefits from receiving it. Keep RFC 0021's existing representation and
consumer acceptance semantics.

## Bounded work

Develop against at most twelve repository identities per extraction wave,
declared before implementation. Include repository and component layouts,
prerequisite chains, ambiguous instructions and stale/conflicting evidence.
The retained PR #179 diagnostic may be adjudicated in full as a separate known
set; select any implementation subset into the development ledger explicitly.
Own extraction and focused fixtures; coordinate changes to shared expectations
and policy rather than widening schemas or promoting component commands to
repository defaults.

The first qualification cohort is 24 tasks: three per repository/component scope
in each of Rust, Python, JavaScript/TypeScript and Go. Use at least twelve distinct
repositories and no more than two tasks per repository. Select from upstream
sources using the shared exclusion and sampling rules. Freeze component paths
and task intent before extraction. These strata intentionally test applicability;
they do not estimate index-wide prevalence. Retain shortages as an incomplete
qualification rather than substituting known development cases.

An assessor outside the implementation assignment freezes acceptable complete
instruction alternatives, source support and reasons for required abstention
before inspecting evaluated extraction. Inspect command, directory, coverage
scope, component, prerequisite completeness and source revision together. A
plausible command with missing context is insufficient. Distinguish a source
assertion from evidence of a successful execution. Source gold can establish
documented applicability without independently executing third-party code.

## Evaluation and outcomes

Freeze extractor source/dependencies, all consulted input bytes, extraction
limits, any escalation model/settings/budget and the consumer policy. Evaluate
each task once with that configuration; retain all candidates and the selected
instruction or rejection. Bind source assessments to the exact tuple. The
qualification does not repair index records or run arbitrary upstream commands.

For every frozen task, record one initial disposition:

- Correctly applicable instruction supplied directly, without upstream fallback.
- Correct abstention: sources or the available profile cannot support an
  applicable instruction under the frozen policy; state the missing evidence.
- Inapplicable or unsupported instruction incorrectly accepted; record each
  mismatched tuple field, including a correct-looking command with wrong scope.
- Supported applicable instruction missed or rejected by extraction/selection.
- Unresolved adjudication or technical failure; keep it in the denominator.

For abstentions, distinguish insufficient upstream evidence from extractor
failure to recover an established alternative. This qualification scores the
need for fallback, not successful fallback or final task completion. Those need
observations from F-05.

The leading establishment metric is correctly applicable direct instructions
divided by all 24 frozen tasks. Also report accepted-instruction precision,
incorrect acceptance per frozen task, correct abstentions and supported misses.
Report raw numerators/denominators by scope and ecosystem, with repository
groupings so two tasks in one project do not imply independent repositories.
Precision with zero accepted instructions is undefined, not 100 percent.
Root scalar coverage is a secondary diagnostic.

## Decision and handoff

Implementation checks use existing importer fixtures and exact expectations;
they establish regression behavior, separately from qualification. To qualify
this bounded wave, require all 24 dispositions resolved, no incorrectly accepted
instruction, and at least one correctly applicable direct instruction in each
scope and ecosystem. Report every miss even if that gate passes. This is a
small qualification bar, not evidence of a zero population error rate or a
required increase in public acceptance counts. All-abstention can demonstrate
conservatism but cannot qualify useful establishment.

Return the development patch and focused checks, frozen split/source manifest,
gold, raw extractor output, per-task adjudications and metric table. A failing
qualification is a valid retained result. Once results are inspected, fixes
receive regression fixtures and a new held-out qualification cohort. No E1 result
closes consumer-benefit, execution-success, release or independent-use gates.
