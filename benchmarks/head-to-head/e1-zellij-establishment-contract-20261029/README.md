# Zellij automatic establishment proposal: no High code change

The documented default instruction is supported, but this packet recommends no
production confidence change. It preserves the unchanged known-development task
`e1-rust-01-repository-tests`, `cargo xtask test`, and binds the source assessment
freeze `11d33120596bfe8cca2d5983f419e80eef17816acaade50bb398d500fc0bc58e`.

The first draft proposed accepting the exact reviewed nine-file source bundle as
a named recipe. The coordinator rejected that production approach: hardcoding an
upstream revision or whole-file fingerprints would compile this investigated
answer into an allowlist, move per-repository facts out of retained evidence, and
show no extractor generalization. The draft is preserved verbatim in
`rejected-fingerprint-option.json`; `rejected-option-disposition.json` explicitly
rejects it. It is neither an implementation specification nor authorization to
raise confidence.

A bounded generic extractor could recover a source-bound candidate from visible
maintainer command/setup prose, the Cargo alias, owning root manifest and declared
toolchain. It would need to preserve the target-dir/environment warning and
conditional GNU Windows linker, rather than flattening them or inventing empty
setup. That supports Medium extraction or abstention when syntax/conditions exceed
the supported form. It does not generally establish the actual default Rust route.
Here, workspace membership, test selection, feature opt-outs, helper calls,
cache/stamp behavior and optional compile checks require independent source
reasoning. No demonstrated small general semantic recognizer covers those facts.
A command token, matched grammar, valid source hash or arbitrary named evidence
flag cannot supply the missing establishment judgment.

The useful result is the retained source assessment: this command is the
maintainer-documented 19-entry default, with declared setup and explicit
environment conditions. That is distinct from an all-21-members claim, guaranteed
native/platform success, automatic High or consumer benefit. Source gold requires
no upstream execution or exhaustive transitive-dependency success proof.
Per-repository investigation belongs in source/value/time-bound evidence under the
existing policy. AI assessments do not mint reviewed/canonical record status.

`recommendation.json` names the minimum positive input paths, semantic blockers,
scope/prerequisite conditions, necessary rejection controls and next gates. Core
context scoring currently caps mechanically intact contextual candidates at
Medium; that remains appropriate without an independently justified semantic
verifier. Current crawler materialization also lacks config/toolchain/xtask bodies;
missing local files cannot stand for upstream absence. No crawler or public-schema
change is proposed here.

Any future automatic High rule needs a separately specified general semantic
contract, independent code/source review and meaningful mutation/held-out tests.
This exposed task cannot be its generalization evidence. If Medium recovery itself
is valuable, it can receive a separate bounded implementation packet; none is
requested or authorized by this proposal. No production, index, frozen history or
source inputs were edited; no network, daemon, package, native task, Cargo,
provider or model action ran. The author retains prior proposal/gold context and
does not claim to be a second independent curator.
