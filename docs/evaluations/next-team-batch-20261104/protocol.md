# Run protocol and accounting — frozen before outcomes

1. Verify `SHA256SUMS` and `SEAL.json`. Record the packet seal, product base commit, accepted entrypoint revision, policy revision, runtime, operator/context identity and run order before starting. Only after minimum D1/PD1 acceptance may outcomes run. Interface mapping must not change questions, evidence, opportunities or thresholds. If unavailable, record blocked/unfinished rather than invent an outcome.
2. Use two isolated stores and fresh consumer contexts with identical initial source-body cache contents, metadata, discovery list, network/fallback permissions, response bodies, validators and source-policy opportunities. Start empty for initial acquisition; both receive the same already-retained source cache after acquisition. Each arm can persist its own notes, source dependencies and original dates and use ordinary search/hash tools. Treatment may additionally use the accepted product interface. Baseline may use metadata and the same source cache, saved notes, dependency hashes, conditional requests and fingerprint/discovery signals. No prewritten findings or oracle assertions are seeds. No free source preloading: source acquisition and cache seeding are counted once per arm; common retained-capture production is a separate indexer cost, currently unmeasured.
3. Deterministic order: baseline first for odd task IDs, treatment first for even task IDs, in isolated contexts. Preserve all attempts, including setup failures, refusal, incorrect claims, unknowns, restarts, timeouts and unfinished work. Run all declared visits/scenarios with no favorable-case exclusion. Finite ceiling: 15 operator minutes per task per visit, 2 attempts per arm per task per visit; an attempt that hits its ceiling is unfinished. No model/provider spending or external network permitted by this local preparation authorization. If model execution later requires paid activity, its own authorization is a real dependency. Record operator/developer controls as such; they do not satisfy independent-use gates.
4. Give a consumer `task-inputs/questions.json` and only the current source catalog/endpoint. Require a decision, requirement-level supported/contradicted/unknown judgments, exact source path/URL plus hash and locator, assumptions, unresolved gaps, original assessment time, current observation time, and what was reread or reused. Statements from a README are evidence of the declaration, not execution, compatibility, performance or correctness. Unsupported positive and negative assertions both count as errors. A justified unknown can complete a scoped decision.
5. At each revisit observe the local source catalog/manifest through the same policy in both arms, validate cached body integrity before use, and reacquire missing/corrupt sources. Any changed dependency reopens affected requirements even if the ultimate answer remains the same. Reusing an unchanged dependency never renews its original interpretation/inspection age. Audit policy is deterministic: one unchanged body per revisit, selected by lexicographic URL/path order round-robin; initial state has full reads. A changed source fetch cannot substitute for the unchanged-body audit. Each arm gets the same audit target, source fallback, cache-loss and failure schedule. Hashing/stat/integrity reads and parsing count as local work. Unknown CPU/tokens/money is null plus reason, never zero.
6. Before oracle access, freeze each arm's output and logs. Independent scoring checks every required assertion and every additional material assertion, source identity, scoped decision, freshness, invalidation, missing source handling and retained unrelated work. Preserve raw outputs. No repair retroactively removes a failed attempt; append repair/replay evidence under a new attempt ID and retain original score. Stop expansion and repair the largest observed gap after the complete bounded run; the original comparison remains reported.
7. Report per-task/per-visit and aggregate counts: correct, incorrect, unknown, missing required judgments, unfinished attempts, useful completed decisions, reopened dependencies, unchanged work retained and any stale conclusions. Compare costs only for equivalent correct completion and freshness; no savings claim if either arm fails quality. No inferential significance or general performance/adoption claim from this small synthetic workload. Publisher setup/update/recovery is unmeasured until D3/PD3; no combined-cost acceptance until those observations join. Separate publisher, indexer/intermediary and consumer costs and shared one-time work from recurring work.

## Required ledger fields

`attempt-ledger.schema.json` specifies required observations. Use JSON Lines, one row for every attempt, plus resource-operation rows linked by attempt ID when needed. Keep requests and response/header/payload bytes separate, and count discovery, conditional/304, acquisition, fallback, audits, failed fetches, retries, serving, cache writes/storage, local integrity reads and parsing. Track preparation, setup, source acquisition, revision checking, publisher update/recovery and answer review separately. Record elapsed wall time and active operator work; CPU, model tokens and money need direct measurement or an explicit unknown reason. Parallel elapsed times are not summed as total wall time. A local zero external-request count does not imply zero local requests or zero cost. Test counts and bytes/4 are not utility or billed tokens.
