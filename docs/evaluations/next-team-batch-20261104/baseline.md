# Competent same-cache baseline

Freeze this procedure before seeing treatment results. The comparator is a competent reader using the same repository metadata/discovery catalog or site discovery/HTTP/fingerprint data, identical source bodies/cache, ordinary text/HTML search, content hashes and a saved decision table with source dependencies. It is not a cold reader forced to redownload everything or forbidden to remember notes.

Initial: inspect discovery/catalog once; select source files from task needs using names/metadata; read and cite raw bodies; write the answer and per-assertion source hash, locator, inspection date, assumptions and gaps. Revisit: read the current source-observation catalog or validate HTTP/manifest/fingerprint state using the frozen freshness policy; verify cache integrity; compare dependency hashes; reread only changed, missing or audited dependencies; preserve usable unrelated notes and original interpretation age. Reopen impacted assertions and save the updated result. Conditional GET/304 and local cache reuse are allowed. Full rereads are allowed but counted. No preauthored expected answers or supplied findings enter either arm.

Both arms get identical raw discovery, manifests/fingerprints, metadata and cache opportunities; the baseline may exploit them all. This isolates any incremental value of the treatment's source-bound workflow/persistence, rather than attributing a shared digest/cache advantage solely to treatment. Additionally report an ordinary ETag+sitemap-only baseline descriptively if desired, with the same audit target/freshness and all costs, but do not substitute it after seeing results or call it the equal-opportunity primary comparator.

Before running, record exact commands/tool revisions for ordinary search, hashing and cache serialization; confirm on a neutral unrelated fixture that the operator can save notes, compare dependency hashes, recover a deleted body and use conditional responses. No task/oracle outcomes are needed for that mechanical rehearsal. Manual reader effort and any baseline glue/serving work count. This is a frozen executable human procedure, not evidence that a baseline outcome has run. D1/PD1 adapter implementation and combined acceptance belong to the coordinator.
