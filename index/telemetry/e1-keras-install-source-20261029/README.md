# Keras local installation source follow-up

The missing helper is now inspected at
`keras-team/keras@7efab4a60f5930fa81b0db15ed4ec6e4925e0c45`. It supports a more
precise description of the documented installation recipe, while leaving the
complete local test instruction unresolved. No extractor or confidence change is
justified by this packet alone.

This is known E1 development material reviewed by the prior Keras extractor/gold
author. It is not a fresh holdout, an independent second curator, native execution,
or consumer evidence. The starting source disposition remains unchanged:
`../e1-keras-source-disposition-20261029/FREEZE.json`, SHA256
`2c53e516f15aafe6c80e16aa2b9ff1b104b2537d0a67857052e8f9737303545d`.

`plan.json` was written before API acquisition. Nine read-only GitHub connector
calls acquired eight full source files totaling 29,118 bytes and exact-commit
metadata. Every file was requested using the declared commit ref; every returned
Git blob SHA matches the locally recomputed Git blob identity. Connector responses,
arguments, selection reasons, URLs, sizes and hashes are retained in `requests/`
and `request-ledger.json`. The commit metadata includes incidental diffs unrelated
to installation; those were not used as installation evidence. Five previously
retained README/contribution/metadata/requirements files were read in place and
hash-bound in `disposition.json`; they were not reacquired or rewritten.

The helper exposes these concrete conditions:

- It invokes `python3 -m build`, then uses `pip3 install` with force reinstall and
  no dependency installation when a matching wheel is found and `--install` was
  requested. The common requirements declare `build`. The PATH-resolved tools are
  not proven to use the launching interpreter's environment.
- It refuses an existing `tmp_build_dir`, copies source and packaging inputs,
  excludes test file suffixes, copies build outputs into `dist`, and has temporary
  cleanup in `finally`. It does not clear an existing `dist`; selecting a filename
  containing the source version is not independently verified fresh-build evidence.
- Before invoking the build frontend, it imports Keras to obtain its version. Its
  initial optional torch import carries a source comment about import ordering and
  a runtime crash. The parent package imports the generated API and a broad source
  tree. This is more than reading a version literal without package initialization.
- The inspected version is `3.16.0`. Optional nightly and RC flags alter copied
  packaging/version data; neither flag is requested by the default README recipe.
- Backend configuration defaults to TensorFlow, reads user/config state through
  `KERAS_HOME` or a home/temp directory, and accepts a nonempty `KERAS_BACKEND`
  override. Backend initialization dispatches to built-in modules or a pluggable
  loader. Backend dependencies are therefore relevant before the wheel build.

`disposition.json` contains ten bounded assertions with whole-file hashes and
exact passage ranges/hashes. It preserves the Python minimum disagreement
(`CONTRIBUTING` says 3.10; project metadata requires 3.11), platform guidance,
requirements markers, backend-version qualifications, and the conditional API
generation instruction. The checked-in API initializer is marked autogenerated;
the helper does not call the API generator. That observation does not establish
that API generation is unnecessary for a PR changing public exports or that the
generated files are consistent.

The eight-file limit stops closure here. Backend implementations, the pluggable
loader, the broader package import tree, and `shell/api_gen.sh` remain uninspected.
External build tools and package resolution were not inspected or executed. The
helper cannot establish that its wheel installation is necessary or sufficient
for every `pytest keras` case, and it does not resolve CI-only setup versus local
backend/task requirements. A narrower future packet would need an explicitly
selected backend/task and authorization to inspect its remaining direct setup and
test references; it must preserve these unresolved conditions until then.
