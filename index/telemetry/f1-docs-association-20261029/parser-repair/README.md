# Generic Markdown documentation association repair

This append-only repair follows the independent two-record correction freeze. It changes only `crates/dotrepo-core/src/import/parsing/markdown.rs` and adds its focused `markdown/docs_tests.rs`. The corrected index records and all original frozen artifacts remain unchanged. Shared fixture expectations, types, crawler and export timestamp semantics are unchanged.

Direct prefixes, documentation-section declarations, standalone/navigation rows and linked documentation badges can establish an entrypoint. Prose must use a bounded direct instruction with a recognized documentation/start label or explicitly identify the current README project as the documentation subject. Arbitrary occurrences of “documentation is available at” and integration possessives do not establish that subject. Getting-started labels match exact generic forms or exact project-qualified forms. A neutral title can follow an explicit start prefix; an explicitly differently named docs/start label cannot borrow that prefix. Domains do not determine ownership: the same integration URL is accepted when directly declared as project docs in the positive control.

Wrapped physical lines share their paragraph subject, including list continuations. A lazy cache renders/scans each encountered paragraph once; nonlink lines do not trigger context work. A deterministic control over a paragraph larger than 1 MiB (20,000 lines, 2,000 linked lines) checks one context build and final abstention without a timing threshold. Explicit badge rows remain independent declarations, preserving the redis-py fixture. This is bounded lexical interpretation, not a full Markdown/HTML implementation or general complexity guarantee for existing per-line link helpers.

The exact retained SwiftLint and MinIO README-only CLI imports both exit successfully and withhold the old wrong-subject values, without guessing replacements. The source test uses SwiftLint's original physical line wrapping and MinIO's client name outside the link label. This demonstrates local extraction behavior on the retained source subset; it is not a complete crawler refresh or external consumer result.

Focused controls: 17 docs-filtered tests (9 new), 31 existing parsing tests, unchanged 2-test import fixture gate, core all-target Clippy, owned-file rustfmt and CLI build pass. `checks/final-command-receipts.json` retains exact final commands and results. Two initial failures are retained, explained in `report.json`, and covered by the passing final controls. No network, provider, package, or upstream code execution occurred. Cargo was released to the coordinator after the focused checks.

`source-bindings.json` binds both source files, the historical before file, base/head, rebuilt CLI and the independent parent freezes. `replay.json` binds the two local importer receipts. `report.json` lists exact limits and remaining independent/integrated gates.
